# Учёт рабочего времени

Локальное веб-приложение для добавления сотрудников, учёта времени по задачам и просмотра отчётов за выбранные даты. Интерфейс на русском языке. Для проверки используйте вымышленные имена и задачи.

## Запуск

Требуется Python 3.11 или новее. Дополнительные пакеты устанавливать не нужно.

```sh
python app.py
```

На Windows также можно использовать `py app.py`. Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Для остановки сервера нажмите Ctrl+C. При первом запуске рядом с `app.py` создаётся файл `tracker.sqlite3`. Чтобы использовать другой файл базы, задайте переменную окружения `TRACKER_DB`.

Добавьте вымышленного сотрудника, например Анну Ветрову. Введите описание задачи, запустите таймер и спустя несколько секунд остановите его. Выберите сегодняшнюю дату в обоих полях отчёта и нажмите «Показать отчёт». Перезапустите сервер и убедитесь, что запись сохранилась. Можно отдельно проверить перезапуск с работающим таймером.

## Правила учёта

- У каждого сотрудника может работать один таймер. Разные сотрудники могут вести задачи одновременно.
- В отчёт попадают завершённые записи. Обе выбранные даты включены и интерпретируются в UTC+05:00. Например, у задачи с 23:59 до 00:02 в отчёт за второй день попадут две минуты.
- Если за период нет записей, приложение показывает нулевой итог и пояснение. Если даты введены неверно, оно показывает ошибку.
- Время начала и остановки сохраняется на сервере с точностью до секунды. Таймер, оставшийся активным при остановке приложения, продолжит отсчёт при следующем запуске. Время, пока сервер был выключен, войдёт в длительность задачи.

## Как устроен код

- `app.py` обрабатывает формы и формирует HTML. После успешной отправки формы сервер перенаправляет браузер на главную страницу, поэтому обновление страницы не отправляет форму повторно.
- `tracker.py` отвечает за операции с SQLite и правила отчёта. Уникальный индекс на незавершённые записи защищает от двух одновременных запусков у одного сотрудника. Остановка привязана к ID конкретного таймера, чтобы старая вкладка не могла остановить следующий.
- `timer.js` обновляет показания на экране. Итоговое время рассчитывается на сервере.
- `test_app.py` проверяет приложение через его HTTP-обработчик с временной базой и управляемыми часами.

## Проверки

```sh
python -m unittest -v
```

На Windows можно выполнить `py -m unittest -v`. Семь тестов покрывают добавление сотрудника, запуск и остановку таймера, восстановление активного таймера и истории, повторный старт до и после остановки, пустой отчёт, раздельные итоги сотрудников, пересечение полуночи и валидацию данных.

## Применение ИИ

Инструмент разработки — OpenAI Codex в ChatGPT, модель семейства GPT‑6. Codex сгенерировал код и тесты, запустил проверки и доработал поведение на основании воспроизведённых ошибок. Во время работы приложения вызовы к ИИ не выполняются.

Первый запрос содержал полное тестовое задание. Ниже примеры формулировок по подзадачам, восстановленные по ходу работы.

1. «Сделай локальное веб-приложение на Python и SQLite. Добавь сотрудников, запуск и остановку таймера с описанием задачи и отчёт по датам».
2. «Проверь повторный запуск и остановку из старой вкладки. Убедись, что после перезапуска приложения сохраняются и работающий таймер, и завершённые записи».
3. «Проверь пустой отчёт, неверный диапазон дат и задачу, которая пересекает полночь. Напиши тесты с фиксированным временем».

### Найденные и исправленные ошибки

| Ошибка | Исправление |
| --- | --- |
| Задача, запущенная и остановленная в первую секунду периода, исчезала из отчёта. Тест с остановкой ровно в полночь воспроизвёл ошибку. | В запросе учтена нулевая запись, совпадающая с началом периода. Она видна в таблице и добавляет к итогу 0 секунд. |
| При обратном порядке дат форма одновременно сообщала об ошибке и показывала «За выбранный период записей нет». | При неверном диапазоне таблицы отчёта скрываются. Для корректного диапазона без записей остаётся отдельное пустое состояние. |

После исправлений весь набор тестов проходит.
